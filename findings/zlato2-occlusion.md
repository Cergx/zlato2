# findings/zlato2-occlusion.md — окклюзия и приоритеты отрисовки, l10_1

Дата: 2026-08-26. Все правки в `src/game/MapRenderer.ts`, `src/game/Game.ts`,
`src/components/gameWindow/GameWindow.tsx` (два последних — только TEMP-хуки,
помечены «remove on approval»). Коммиты НЕ делались — ждут одобрения.

## O1. Сцена-объекты (статики/анимации) не перекрывают себя масками

**Симптом.** «Исчезновение статики, когда юнит стоит за стеной и статиком».

**Байты.** `Client.dll` (base 0x12000000, G:/ws/zlato2/game) `ApplyCellMask`
0x1202F251..0x1202F413 + блиты ..0x1202F5CD — виртуальная функция
(`call *0x20(%eax)`), прямых call-сайтов нет; вызывается на каждый шаг
ходящего юнита (entity-local). Дизассемблер: /tmp/client.asm, строки 56306+
(из objdump). Структура: camera-relative координаты (глобы 0x12111300..30),
fetch тайла `(%ecx,%edx,8)` (8-байтные записи), тест $0x40000000 → выбор
main(0x114)/alternate(0x110) массивов (= порт `alternateForeground` ✓),
клип-дистанции (сравнения 0xb4/0xb8), затем 4 условных RLE-блита
(call 0x12015D38) полосами 18/24 px и центральный блит — 9-slice клип по
энтити-ректу. Семантика совпадает с портом MaskCompositorRuntime ✓.

**Вывод.** ApplyCellMask — механизм ПЕРСОНАЖЕЙ (перекрытие юнита объектом).
Рисовать форграунд масок поверх статиков/анимаций — ошибка порта.

**Правка.** `drawAnimation`/`drawStatic`: `drawOccluders(...)` удалён
(остался только у `drawPerson`).

## O2. Скрытая причина: scenery-статики вообще не рисовались

**Симптом (тот же пользовательский).** Статик «исчезает» у стены — на самом
деле static_2/3/4 (не дверные) НЕ РИСОВАЛИСЬ НИКОГДА: фильтр
`createBackgroundStatics`: `(param1 & STATIC_SCENERY_VISIBLE=0x2) !== 0`,
а у ВСЕХ статиков l10_1 `param1=1` → 1&2=0 → мимо. Дверные (0,1,5,6) рисовались
через renderQueue.

**Данные.** Опрос SDSC 10 уровней браузерным парсером байтов BLK_SDSC
(u16@0=param1, u16@2=param2): param1 ∈ {1,3} везде, param2 ≡ 2:
l10_1 7×(1/2); l10_2 {1/2:2, 3/2:2}; l12_1 {3/2:1, 1/2:3}; l12_2 {1/2:3, 3/2:2};
l13_1 {1/2:2, 3/2:3}; l14_1 2×(1/2); l19 3×(1/2); l1_1 2×(1/2); l3_1 {1/2:7, 3/2:6};
l7_1 {1/2:3, 3/2:1}. Флаг 0x2 на param1 осмыслен (делит статики на 2/3 подмножества),
НО исключать param1=1 из отрисовки — неверно.

**Байты.** Нативный диспетчер world-объектов 0x1202C6F0: `kind = desc->[+0x2C]&0x1F8`
— согласуется с kind = param1<<3 (1→8, 3→24; оба ≠ 0 → обе категории попадают
в единый depth-список). Точного маппинга +0x2C нет (структура нативной записи
не восстановлена) — помечено как гипотеза, согласующаяся с данными.

**Правка.** `createRenderQueue` пушит ВСЕ статики со спрайтом (дверные и
scenery) в единый depth-сортированный список; механизм `backgroundStatics`
(`createBackgroundStatics`, `drawBackgroundStatic`, поле, вызов) удалён полностью.
`renderDepth(static) = doors depth ?? position.y + image.height` — без изменений.

**Проверка.** static_2 (1125,365) 55×128: попиксельное сравнение канваса со
спрайтом при `dayNightEnabled=false` → **matchPct=100%** (было: статик
отсутствовал). ВАЖНО: замер при включённом ночном затенении даёт 5.4% —
артефакт затемнения, не баг (сравнивать надо с учётом day-night multiply).

## O3. transparentOccluders — шахматная клетка вместо alpha 0.58

**Было.** `ctx.globalAlpha = this.transparentOccluders ? 0.58 : 1` — равномерная
полупрозрачность (неправильная, alpha 0.58 — из старой версии).

**Стало.** В `drawOccluders` при `transparentOccluders=true`: форграунд маски
рисуется в temp-канвас размера клип-ректа (клип-рект = рект спрайта юнита —
зона фактического перекрытия), затем `destination-in` паттерном 2×2
(непрозрачны (0,0) и (1,1)); результат обратно на основной канвас. Объект
сохраняет каждый второй пиксель, юнит просвечивает в шахматном порядке
строго внутри зоны перекрытия; вне её — сплошной форграунд.

**Проверка.** Игрок за стеной (1180,400): пиксельный диф вкл/выкл = 648 px
(≈ половина силуэта) в боксе (494..533, 246..328) = рект спрайта игрока;
4×-кроп → инспекция: «character silhouette showing through the wall in
checkerboard pattern, localized to the character footprint» ✓.

## O5. BLOCKED: игрок на веранде «закопан» (1180,500)

Игрок на веранде перед дверью скрыт форграундом маски 37 (виден только шлем).
Данные собраны:
- Якорь ступней (1180,500) → ячейка (49,27); селекция findNativeOccluders
  возвращает маску 37, damage 3291 px в ректе спрайта.
- Terrain-дамп маски 37 (строки 16..29, x=45..54): строки 17..23 — 0xFF87/0xFF89
  (terrain&2 ✓), строка 24: …63365,64389…; строка 27: 0007,2567,12167,65415,65415;
  строка 28: 0001,0005,3845,44933,65413. Старший байт = паттерн занятых
  субтайлов чанка (CC/55/AA/FF — квадранты), младший — флаги.
- Ручная трассировка `maskExtendsPastAnchor` по дампу НЕ воспроизводит выбор
  маски 37 на (49,27) — реальный слот-лейаут чанка не восстановлен (в ячейке
  до 4 масок по слотам (cx&1|cy&1<<1); дамп печатал только первый слот с maskIndex=37).
- Дизассемблер: boundary-логика terrain&2 в теле ApplyCellMask отсутствует —
  в vtable-caller'е, статически недоступном.

3 попытки разрешить семантику исчерпаны. Требуется нативное сравнение:
стать игроком на веранде перед дверью в нативной игре — виден или скрыт?
Если виден — критерий отбора масок в `findNativeOccluders` нужно править
(кандидат: требовать непрерывной полосы terrain&2 вниз от якоря до низа региона).

## O6. l1_3: герой в тайлах (272,86)/(271,87)/(273,86) рисовался «за стеной» (маска 55)

**Симптом.** На начальной локации l1_3 герой на клетках (272,86), (271,87),
(273,86) перекрывался форграундом маски 55, хотя стоит ПЕРЕД ней. Подтверждено
в рантайме: `__occlDebug.selected` на (3264,774) = `[22,18,55]`, т.е. маска 55
ложно селектится.

**Корень.** `maskExtendsPastAnchor` (MaskCompositorRuntime.ts) — ЭВРИСТИКА-порт,
неверная. Вертикальный скан ищет boundary-плитку (`terrain & 2`) в столбце
`startX` (колонка цикла по кадру), а не в столбце якоря энтити. Для диагонального
фронта маски 55 (front edge: (134,41),(135,41),(136,42),(137,43)) при якоре
(136,43): цикл доходит до x=137 (slot 0), boundary-плитка (137,43) лежит в СТРОКЕ
якоря, но восточнее героя — скан в x=137 немедленно возвращает true. В столбце
героя (136) фронт маски 55 на y=42 (СЕВЕРНЕЕ якоря y=43) → герой спереди.

**Попытка `startX→anchorCellX` — ОТКЛОНЕНА.** Регрессионный sweep (208 тайлов,
область 265..280 × 80..92) показал массовое снятие 18/19/20/22 (69 тайлов
изменили выбор). Правка откачена, код возвращён к исходному состоянию.

**Нативный алгоритм (дизассемблер, Client.dll base 0x12000000).**
Селекция НЕ является frame-column скан + boundary-эвристикой. Натив:
- **Таблицы строятся при загрузке уровня** в `0x1202BD1F..0x1202BEFF`:
  `0x838c[slot]` — флаг «слот участвует» (`movl $1, 0x838c(%edx,%eax)` @0x1202BE64);
  `0x839c[slot][subcell]` — ожидаемый maskIndex (stride 60 байт на слот,
  `movl %edx, 0x839c(%eax,%edi,4)` @0x1202BE84). Строится сканированием
  тайлов маски с проверкой bit0 (маска) + bit1 (boundary) @0x1202BE02..BE2D.
- **Lookup на каждый кадр** в `0x1202F17C` (вызывается из `0x1202CDF1`):
  читает maskIndex из `chunks[anchorCellX] + 40*anchorCellY + 16 + 4*slot`
  (только ЯЧЕЙКА ЯКОРЯ, 4 слота), условие отбора
  `flag[slot] && maskIndex == expectedMask[slot][arg2]`, где `arg2 = ecx % 0x84b8`
  (суб-индекс в пределах футпринта энтити).
- Зов из `0x1202CCFB..0x1202CE16`: цикл по клеткам футпринта энтити
  (`0x8524[]`/`0x8d24[]` = anchor X/Y по клетке), для каждой клетки отдельный
  вызов селекции.

**Нужно для корректной правки** (не сделано — риск ещё одной неверной
гипотезы): расшифровать точное правило построения `0x839c` (что именно кладётся
в expectedMask по суб-ячейке), семантику `arg2`/`0x84b8` (ширина футпринта) и
полный цикл `0x1202BD1F`; затем портировать «построение таблиц при загрузке +
lookup по якорю» вместо текущей эвристики. Кандидат на goldenLand2-агента
(дизассемблер готов, см. .tmp/Client.full.dis).
