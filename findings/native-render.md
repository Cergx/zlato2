# Нативный рендер GoldenLand 2 — модель из дизасма Client.dll

Дата: 2026-09-09. База: `G:/ws/zlato2/.tmp/Client.full.dis` (objdump AT&T, base `0x12000000`, VA == runtime VA).
Все адреса/строки проверены чтением листинга в этой сессии, кроме помеченных `[INFERENCE]`.
Заменяёт устаревшие разделы O5/O6 в `zlato2-occlusion.md` (эвристика `maskExtendsPastAnchor` — неверна).

## 1. Координатная сетка

- Чанк 24×18 px, субячейка (тайл) 12×9 px (`WorldCoordinates.ts` ✓).
- Чанк-запись MHDR: 4 слота (слот = субячейка чанка: `slot=(tx&1)|(ty&1)<<1`), 6 байт/слот:
  `terrain u16, flags u16, maskIndex i16`. Биты terrain: **bit0 = маска присутствует, bit1 = boundary
  (передняя кромка), bit2 = blocked (NO_WAY), bit30 (в runtime-расширенном флаге) = закрытая дверь**.
- Парсер `LVLParser.parseMaskHDR` ✓ (layout совпадает).
- Старший байт terrain — квадрантный паттерн субтайлов (CC/55/AA/FF и комбинации).

**Уточнение (пост-совет, байт-точно):** пределы сканов 0x95a0/0x95a4 — это константы карты
(ширина/высота в чанках), записанные ОДИН РАЗ при инициализации уровня писателем 0x1202E370
(out-параметры vtable *0x44 менеджера 0x12110f3c; там же this+0x8344 = chunkArray). Запись
0x12110428 (52528/52539) — отдельный абсолютный глобал (копия числа строк сетки), НЕ this+0x95a0.
⟹ сканы НЕ вырождены: phase1 — реальный скан вправо до bit1 (предел = ширина карты; условие
`x ≥ 0x9588` всегда истинно, т.к. chunkX ≥ leftBound объекта ≥ leftBound камеры), phase2 —
реальный скан ВНИЗ (юг) до bit1 (предел = высота карты). Регистрация требует ОБА скана.
Форма «bit0&&bit1 на якорной ячейке» — лишь частный случай; на l1_3 (bit1 стоит на всех
масковых ячейках) результаты совпадают, но портом реализована полная двусканная форма
(scanEastBoundary/scanSouthBoundary в MaskCompositorRuntime.ts) — она же восстанавливает
ранее пиксельно проверенное поведение (юнит за шатром/стеной).
## 3. Init сетки (0x1202BF60, вызывается per-entity функцией 0x1202C8AC)

**КЛЮЧЕВОЕ (52294-52305, 52560-52591): глобалы 0x12110400..0c — это рект самого
отрисовываемого объекта, НЕ камеры:**

- kind 1/3/4 → 0x1202c399: `minX=[d+0x2c], minY=[d+0x30], maxX=minX+[d+0x14]−[d+0xc]+[d+0x18]+1,
  maxY=minY+[d+0x18]−[d+0x10]+1`.
- kind 2 → 0x1202c3d5: `minX=[d+0x34], minY=[d+0x38], maxX=minX+[d+0x24]−[d+0x1c]+1,
  maxY=minY+[d+0x28]−[d+0x20]+1`.
- Затем общий кламп (52309-52323): `minX = max(minX, scrollX); maxX = min(maxX, scrollX+0x95c4−0x95bc)`
  (и аналогично по Y) — пересечение ректа объекта с экраном.

Далее (kind-агностично):

1. leftBound = minX/24 (magic 0x2AAAAAAB) → 0x12110410 = 0x9588 (52325-52332).
2. colCount = (maxX/24)+1 − leftBound, кламп ≤13 (52375-52378); граница карты через 0x95a0
   (52414-52420).
3. Таблицы колонок: 0x84bc[col] = leftBound+col; 0x84f0[col] = anchorRow (52379-52392).
4. bottomRow = (maxY−minY)/18 + 2 (52477-52488) — строки ректа объекта +2 запаса.
5. topRow = anchorRow − ([d+0x30]+[d+0x18]−[d+0x10]+1)/18 (52401-52413, kind 1/3/4).
6. Сетка ячеек (row-major, 52489-52526): row 0..bottomRow−1, col 0..colCount−1:
   `anchorX[i]=leftBound+col; anchorY[i]=anchorRow−row; i=row*colCount+col`; cellCount=0x9524.
   **row 0 = строка ног объекта**, рост row → вверх (chunkY уменьшается).

Рантайм-снапшот (0x12110400..0c = 3301..3331 × 966..1040): это рект СТАТИКА-СТЕНЫ (30×74 px),
клампнутый к экрану: leftBound=137, anchorRow=1040/18=57 (строка ног стены!), colCount=2,
bottomRow=74/18+2=6, cellCount=12 ✓. Ранее ошибочно трактовался как камера.

Семантика: **окклюзия/форграунд привязана к ректу объекта: якорные ячейки (bit0 + оба скана до
bit1) — на строке ног объекта в его же колонках; маски применяются строками выше в пределах его
ректа.**


## 4. Build таблиц (0x1202BC54; вызов per колонку: 0x1202CAD4, col < 0x84b8)

Аргументы: arg0 = 0x84bc[col] (chunkX), arg1 = 0x84f0[col] (=anchorRow), ecx = this;
column index = 0x5c(esp) (pushed счётчик колонки). Внутри — цикл slot 0..3 (52241):

1. `expected = maskIndex(chunkX, anchorRow, slot)` (52144-52146, поле +0x10+4*slot).
2. Флаги ячейки (chunkX, anchorRow, slot): bit0 должен быть 1 (52170), иначе слот мимо.
3. Right-скан (52166-52185): x от chunkX вправо, пока bit0 && maskIndex==expected; первый bit1
   → phase1=1 (условие `x ≥ leftBound(0x9588)` всегда истинно: chunkX ≥ leftBound объекта ≥
   leftBound камеры, а x только растёт). Предел: `x++ ≥ 0x95a0` (ширина карты) → выход.
4. Down-скан (52193-52214): y от anchorRow ВНИЗ по миру (юг), пока bit0 && maskIndex==expected;
   первый bit1 → phase2=1 (0x1202bf02). Маска сменилась/bit0 пропал → стоп без регистрации.
   Предел `y ≥ 0x95a4` (высота карты). Оба предела — константы уровня (setup 0x1202E370),
   НЕ «мелкие значения» — сканы НЕ вырождены (см уточнение в §2).
5. Регистрация (0x1202be48, 52216-52235): phase1 && phase2 → `flag[slot]=1;
   expectedMask[slot][col] = expected`.
6. Return: 1, если хоть один слот колонки зарегистрирован (0x3cesp).
**Итог: регистрация слота ⟺ bit0 на якорной ячейке (leftBound+col, anchorRow, slot) && оба скана
дошли до bit1 в том же mask-run: вправо по строке и вниз по колонке. expectedMask[slot][col] =
maskIndex якорной ячейки.** Форма «bit0&&bit1 на самой якорной ячейке» — частный случай (bit1
уже в якорной ячейке); ранее ошибочно считалась общей из-за неверных пределов (см §2).
Порт: scanEastBoundary/scanSouthBoundary (MaskCompositorRuntime.ts) — полная двусканная форма;
на l1_3 результаты совпадают со строгой формой, но восстанавливают пиксельно проверенный случай
юнит-за-шатром. [Код сканов прочитан байт-точно, 52143-52242; пределы — setup 0x1202E370,
54808-54825]

## 5. Per-entity функция (0x1202C8AC) — порядок за объект

Вызывается из frame-функции 0x120287A0 **трижды на drawable** (48080/48105/48129) c kind 1, 2, 1
(дескриптор 0x1210fd20; спрайты 0xe0/0xe4 дескриптора → 0x8494/0x8496).

1. Init сетки (§3).
2. Предпетля-1 (53027-53056): по колонкам вьюпорта на якорной строке: если НИ у одного слота нет
   bit0 → gate=1 → обычный dispatch (4→0x1202C6F0, 3→0x1202C868, иначе 0x1202C424) → return.
   Иначе gate=0 (0x8490=0) → пересборка таблиц (clear + build per col).
3. После пересборки: 0x8490 = 0, если ХОТЯ БЫ ОДНА колонка что-то зарегистрировала
   (53130-53132: build вернул ≠0 → 0x8490=0). 0x8490 ≠ 0 → обычный dispatch, return.
   0x8490 == 0 → окклюзионный проход (ниже).
4. Предпетля-2 (0x1202cb5e): по ячейкам сетки (0..cellCount−1): цепочка bit0 по 4 слотам;
   если у ячейки slot3 имеет bit0 → 0x1202ce19 — прямой композит маски ячейки в поверхность
   (rep movs, режим 0x12106bf8+0x8c==2 → заливка 0xFFFFFFFF), затем продолжение петли.
5. Dispatch по kind (53257-53274), затем LOOKUP-петля (0x1202ccfb):

```
for i in 0..cellCount-1:                    # i = 0x12110430
    cellX = anchorX[i]; cellY = anchorY[i]
    0x8498 = 24*cellX − scrollX + 0x95bc    # экранный X ячейки
    0x849c = 18*cellY − scrollY + 0x95c0
    если 0x8498 < 0: 0x84a8 = −X, X=0       # клип слева
    если 0x849c < 0: 0x84ac = −Y, Y=0
    clipW = entW − X; 0x84a0 = min(24, clipW); 0x84b0 = 24 − 0x84a0
    clipH = entH − Y; 0x84a4 = min(18, clipH); 0x84b4 = 18 − 0x84a4
    lookup(this, cellX, cellY, i % colCount, mode=1)   # 53335-53344
```

## 6. Lookup (0x1202F17C) → ApplyCellMask (0x1202F251)

```
for slot in 0..3:
    maskIndex = chunk(anchorX, anchorY, slot).maskIndex     # +0x10+4*slot, → глобал 0x12111330
    0x12111308 = slot
    if mode == 0: match ⟺ maskIndex != −1                  # уровень-форграунд (без таблиц)
    else:         match ⟺ flag[slot] && maskIndex != −1 && maskIndex == expectedMask[slot][col]
    на match: ApplyCellMask(maskIndex) — TAIL CALL (55857-55858)
```

ApplyCellMask (геометрия, 55862-56071):
- relX = 24*anchorX − cam.x; relY = 18*anchorY − cam.y; заливки/полосы:
  leftCut = max(0,−relX) (0x1211130c), topCut = max(0,−relY) (10), видимая W = 24+relX−leftCut,
  обрезается также шириной маски-плитки (0xb4/0xb8 структуры плитки) → rightCut/bottomCut.
- 5 блитов (0x12015D38) куска плитки на (0x8498−0x84a8, 0x849c−0x84ac): left-полоса (w=leftCut),
  top-полоса (h=topCut), right-полоса, bottom-полоса, центр (src 0x8364, arg=1).
  Источник плитки: chunk-флаг → test bit30 → main(+0x114)/alternate(+0x110) таблица масок-плиток
  (stride 200), индекс = [cam-менеджер+0xc].
- Семантика для порта: **кусок маски-плитки ячейки, пересечённый с ректом объекта, поверх объекта.**

## 7. Плиты/слоты — маппинг на zlato2

- Порт: `MaskHDR.chunks[x*height+y][slot]` ↔ натив chunkArray[chunkX] + 40*chunkY + 4*slot (flags),
  +0x10+4*slot (maskIndex). Слот = субячейка чанка: (tx&1)|(ty&1)<<1 ✓.
- В l1_3 у всех масковых ячеек `maskIndex=0`, у пустых `0xFF00` (−256) → нативное сравнение
  «maskIndex == expectedMask» фактически = «обе ячейки масковые в одной колонке».

## 11. Полная реверс-модель куска (2026-09-09, ночь) — исправление «mask#19 перекрывает всех»

### 11.1. Что такое кусок на самом деле

- Листы масок l1_3 — ЧИСТЫЕ СТЕНСИЛЫ: классы пикселей = только fill + magenta, art = 0
  (декод `.tmp/mask_sheet_decode.cjs`, зеркалирует портовый CSXParser: alpha = 255−a,
  magenta = r>253&&g<2&&b>252, index −1 → fillColor).
- **Кусок = fill-область листа** (НЕ magenta-форма!): у ApplyCellMask блит листа
  цветоключевой, magenta = ключ (прозрачность). Проверка устранением: у стены
  (mask[19]=sheet52 @(3323,531)) fill на ректе Котара = 0 px, magenta = 3400/3400;
  у стола (mask[21]=sheet19 @(3377,578) = позиция триггера T10) fill = 1001 px
  на нижней части. Нативно Котар дизерится ТОЛЬКО столом → кусок = fill-область.
- HEAD-логика `extractMaskForeground` (terrain − destination-out(лист с magenta-opaque)
  = terrain на fill-области) давала ПРАВИЛЬНУЮ область. Регрессия «перекрывает всех» =
  инверсия области (terrain на magenta) в изменённом composeMaskForeground.
- Гейта глубины «за/перед» В ApplyCellMask НЕТ (0x1202f17c..f7b3: только slot-flag +
  maskIndex≠−1 + cache-equality; клип = rect листа ∩ ячейка 24×18; «за/перед» выводится
  из того, что маска регистрируется только в ячейках, которые она занимает).
